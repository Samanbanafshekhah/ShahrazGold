# راهنمای جامع شهرازگلد

**راهنمای بهره‌برداری، توسعه و استقرار · نسخهٔ ۱٫۰ · ۲۰ مهر ۱۴۰۵ / ۱۲ اکتبر ۲۰۲۶**

این سند بر اساس کد موجود در شاخهٔ `api-mali` تهیه شده است. مخاطب آن مدیر سامانه، تیم توسعه و مسئول استقرار است. تمام نمونه‌ها آموزشی‌اند و شامل کلید یا رمز واقعی محیط نیستند.

## ۱. معرفی و نقشهٔ سامانه

شهرازگلد یک سامانهٔ مدیریت قیمت و ثبت درخواست خرید و فروش طلا و سکه است. مشتری قیمت قابل دسترس برای نقش خود را می‌بیند، معامله را پیش‌نمایش می‌کند و درخواست می‌فرستد؛ مدیر قیمت‌ها، دسترسی‌ها و درخواست‌ها را مدیریت می‌کند.

ثبت درخواست در سامانه، به‌معنای پرداخت بانکی یا تسویهٔ خودکار نیست. چرخهٔ درخواست با بررسی و تغییر وضعیت توسط مدیر ادامه پیدا می‌کند.

| بخش | مسئولیت |
| --- | --- |
| پنل مشتری | مشاهدهٔ قیمت، پیش‌نمایش خرید یا فروش، ثبت و پیگیری درخواست |
| پنل مدیر | مدیریت محصول، قیمت، کاربران، نقش‌ها، درخواست‌ها، اطلاعیه و پیامک |
| اتصال هوم‌گلد | دریافت قیمت خرید و فروش و به‌روزرسانی محصولات متصل |
| API لاراول | احراز هویت، محاسبهٔ قطعی قیمت، اعتبارسنجی و ثبت اطلاعات |
| زمان‌بندی | اجرای دریافت قیمت خودکار مستقل از باز بودن مرورگر |

مسیرهای اصلی ورود: `/login` برای مشتری و `/admin-login` برای مدیر. پنل مدیریت از `/admin` و اتصال هوم‌گلد از `/admin/homegold` در دسترس است.

### مسیر کلی داده

```text
هوم‌گلد ← دریافت قیمت توسط سرور ← ثبت قیمت و نسخهٔ محصول
                                     ↓
                               نمایش در پنل مشتری
                                     ↓
                 پیش‌نمایش معامله ← ثبت درخواست ← بررسی مدیر
```

مرجع قیمت و مبلغ نهایی، بک‌اند است. اعداد نمایش‌داده‌شده در مرورگر جایگزین محاسبات قطعی سرور نمی‌شوند.

## ۳. راه‌اندازی محلی

### پیش‌نیازها

برای محیط توسعه PHP مطابق `composer.json`، Composer، Docker Compose و Node.js 22.12 یا جدیدتر در نظر بگیرید. افزونهٔ `bcmath` برای محاسبات اعشاری ضروری است. Composer هنگام نصب، سازگاری نسخهٔ PHP و افزونه‌ها را بررسی می‌کند؛ نسخهٔ مناسب اجرای تست ممکن است با نسخهٔ مورد نیاز خود برنامه متفاوت باشد.

### نصب اولیه روی محیط تازه

دستورها را از پوشهٔ `shahrazgold-app` اجرا کنید. کپی فایل نمونهٔ محیط فقط برای محیطی است که هنوز `.env` ندارد؛ تنظیمات محیط موجود را جایگزین نکنید.

```bash
cp .env.example .env
composer install
npm --prefix frontend ci
php artisan key:generate
npm run build
docker compose up -d --build
docker compose exec -T app php artisan migrate
docker compose exec -T app php artisan db:seed
```

Seeder برای توسعه است و اجرای آن در production مسدود می‌شود. کاربران نمونه با رمز تصادفی ساخته می‌شوند؛ رمز عمومی ثابتی برای ورود وجود ندارد. برای محیط واقعی از فرایند ساخت مدیر اولیه در فصل استقرار استفاده کنید.

### آدرس‌های این محیط محلی

| سرویس | آدرس در زمان تهیهٔ سند |
| --- | --- |
| فرانت با تغییرات زنده | `http://localhost:8080` |
| سایت ساخته‌شده و API | `http://localhost:8081` |
| پنل اتصال هوم‌گلد | `http://localhost:8080/admin/homegold` |
| بررسی سلامت لاراول | `http://localhost:8081/up` |

پورت پیش‌فرض فایل نمونه ۸۰۸۰ است؛ پورت ۸۰۸۱ مربوط به تنظیمات محلی فعلی است. برای نمایش پورت‌های واقعی از دستور زیر استفاده کنید:

```bash
docker compose ps
```

### توسعهٔ زنده در کنار Docker

وقتی بک‌اند روی پورت ۸۰۸۱ اجراست:

```bash
VITE_API_PROXY_TARGET=http://127.0.0.1:8081 \
  npm --prefix frontend run dev -- --host 127.0.0.1 --port 8080
```

این روش درخواست‌های `/api` را به بک‌اند کانتینری می‌فرستد. دستور `composer run dev` هم برای اجرای سرویس‌های توسعه وجود دارد، اما تنظیمات اتصال دیتابیس و Redis باید متناسب با اجرای PHP روی میزبان باشد. نام‌های `postgres` و `redis` در شبکهٔ Docker قابل دسترس‌اند.

### آماده‌سازی برای معامله

1. دسته و محصول فعال باشند.
2. نقش مشتری به محصول دسترسی داشته باشد و مجوز خرید لازم را دریافت کرده باشد.
3. برای محصول قیمت معتبر ثبت شده باشد.
4. وضعیت مدیر آنلاین باشد؛ آفلاین بودن مدیر مانع ثبت درخواست جدید می‌شود.
5. خرید یا فروش محصول از پنل بسته نشده باشد.
6. محدودیت باقی‌ماندهٔ مشتری برای خرید کافی باشد.

برای محصول خودکار، ابتدا اتصال هوم‌گلد را ذخیره کنید و منتظر دریافت موفق بمانید. در حالت خودکار، تغییر مستقیم قیمت دستی مسدود است. برای بازگشت به مدیریت دستی، روش استفادهٔ اتصال را روی «دستی» ذخیره کنید.

## ۵. اتصال هوم‌گلد؛ راهنمای عملی

### تنظیم اتصال سرور

در `.env`، اطلاعات اختصاصی حساب هوم‌گلد را وارد کنید:

```dotenv
HOMEGOLD_CLIENT_ID=your-client-id
HOMEGOLD_CLIENT_SECRET=your-client-secret
HOMEGOLD_BASE_URL=https://homegold750.ir
HOMEGOLD_TIMEOUT=15
HOMEGOLD_TOKEN_TTL=300
HOMEGOLD_CACHE_STORE=file
```

پس از تغییر تنظیمات:

```bash
docker compose exec -T app php artisan config:clear
docker compose exec -T app php artisan homegold:commodities
```

احراز هویت با `POST /ExternalPartnerAuth/token` انجام می‌شود و قیمت‌ها از `GET /PartnerAPI/Ordering/ExternalPartner/commodity` دریافت می‌شوند. توکن در سرور کش می‌شود؛ قیمت‌ها در هر دریافت مجدداً از سرویس خوانده می‌شوند. بعد از پاسخ ۴۰۱، توکن پاک و درخواست فقط یک بار تکرار می‌شود.

### تنظیم از پنل

1. وارد «اتصال هوم‌گلد» شوید.
2. در صورت نیاز «دریافت قیمت» را بزنید تا فهرست محصولات منبع دیده شود.
3. محصول شهرازگلد را انتخاب کنید.
4. محصول متناظر هوم‌گلد را از فرم یا با کلیک روی کارت قیمت انتخاب کنید.
5. واحد پول دریافتی را مشخص کنید: ریال یا تومان.
6. روش استفاده را روی «خودکار» یا «دستی» قرار دهید.
7. «ذخیره تنظیمات» را بزنید. برای دریافت فوری در حالت خودکار، «دریافت و اعمال الآن» را بزنید.

### فرم سادهٔ فعلی

| فیلد قابل تنظیم | معنی |
| --- | --- |
| محصول متناظر در هوم‌گلد | شناسهٔ محصولی که قیمت از آن دریافت می‌شود |
| روش استفاده | فقط خودکار یا دستی |
| واحد پول قیمت دریافتی | ریال بدون تبدیل؛ تومان با ضرب در ۱۰ |

بخش‌های تنظیم جهت خرید و فروش، تعدیل درصدی و ثابت، تقسیم قیمت، فاصلهٔ دریافت و مهلت اعتبار از فرم حذف شده‌اند. تنظیمات قدیمی این موارد در محاسبهٔ جدید نادیده گرفته می‌شوند. حالت قدیمی «پیش‌نمایش» در پنل به‌صورت «دستی» نمایش داده می‌شود؛ دکمهٔ محاسبهٔ پیش‌نمایش همچنان برای مشاهدهٔ نتیجه وجود دارد.

### تبدیل و نمایش قیمت

```text
قیمت خرید پایهٔ مشتری = buyPrice × تبدیل پول
قیمت فروش پایهٔ مشتری = sellPrice × تبدیل پول
تبدیل پول: ریال = ۱ / تومان = ۱۰
```

مثال آموزشی: اگر `buyPrice=1000` و `sellPrice=900` باشد و واحد منبع را تومان انتخاب کنید، قیمت خرید پایهٔ سایت ۱۰٬۰۰۰ ریال و فروش پایه ۹٬۰۰۰ ریال می‌شود. تعدیل نقش و قواعد اختصاصی مبلغ معامله بعداً در مسیر سفارش اعمال می‌شوند.

کارت‌های بالای صفحه عین اعداد منبع را نشان می‌دهند؛ واحد آن‌ها واحد دریافتی هوم‌گلد است. قیمت پیش‌نمایش و قیمت ثبت‌شدهٔ سایت به ریال است. کارت محصول انتخاب‌شده اول قرار می‌گیرد و زمان آخرین دریافت و وضعیت تازگی قیمت نمایش داده می‌شود.

## ۶. زمان‌بندی، تازگی و خطای قیمت

### پاسخ روشن به سؤال دریافت خودکار

برای محصولی که اتصال «خودکار» دارد، دریافت قیمت با زمان‌بندی سرور هر ۱۰ ثانیه اجرا می‌شود؛ باز بودن پنل لازم نیست و فشار دادن دکمه در هر نوبت لازم نیست. این رفتار به فعال بودن Scheduler و پاسخ موفق هوم‌گلد وابسته است؛ کندی یا خطای سرویس می‌تواند دریافت موفق را عقب بیندازد.

| رفتار | زمان یا شرط |
| --- | --- |
| بررسی و دریافت خودکار محصول | هر ۱۰ ثانیه روی سرور |
| تازه‌سازی وضعیت پنل باز | هر ۱۰ ثانیه |
| درخواست قیمت تازه از پنل | هنگام نبود داده یا قدیمی‌تر بودن آن از ۱۵ ثانیه |
| نشان «دریافت تازه» | وقتی سن داده کمتر از ۳۰ ثانیه است |
| اعتبار قیمت برای سفارش خودکار | ۱۸۰ ثانیه از آخرین دریافت موفق |

نشان تازگی بالای صفحه مربوط به سن فهرست دریافتی است. اعتبار معامله به اتصال همان محصول و آخرین دریافت موفق آن وابسته است؛ ممکن است دریافت کلی تازه باشد ولی یک محصول خطا داشته باشد.

در حالت دستی، Scheduler قیمت محصول را تغییر نمی‌دهد. پنل باز می‌تواند فهرست هوم‌گلد را تازه دریافت کند، اما این دریافت قیمت دستی سایت را بازنویسی نمی‌کند.

### اجرای Scheduler

در Docker:

```bash
docker compose up -d scheduler
docker compose exec -T app php artisan schedule:list
```

در اجرای مستقیم:

```bash
php artisan schedule:work
```

روی cPanel، یک Cron دائمی با مسیر واقعی PHP و حساب خود تعریف کنید:

```cron
* * * * * /usr/local/bin/php /home/ACCOUNT/shahrazgold-app/artisan schedule:run >> /dev/null 2>&1
```

Cron هر دقیقه شروع می‌شود و Laravel برای کار زیر یک دقیقه، نوبت‌های ۱۰ ثانیه‌ای را تا پایان همان دقیقه اجرا می‌کند. هاست باید اجازهٔ زمان اجرای کافی بدهد.

### رفتار هنگام خطا

اگر اتصال شکست بخورد، قیمت قبلی حفظ و خطا ثبت می‌شود. اگر اعتبار ۱۸۰ ثانیه‌ای تمام شود یا هنوز دریافت موفقی وجود نداشته باشد، پیش‌نمایش و ثبت سفارش آن محصول متوقف می‌شود. دریافت موفق بعدی اعتبار را تازه می‌کند.

قیمت یکسان، سابقهٔ جدید نمی‌سازد و فقط زمان اعتبار را تازه می‌کند. تغییر قیمت خرید یا فروش، سابقه و نسخهٔ جدید محصول می‌سازد. قفل همگام‌سازی از اجرای هم‌زمان جلوگیری می‌کند؛ خطای یک محصول مانع بررسی سایر محصولات نمی‌شود.

## ۷. قیمت‌گذاری و چرخهٔ معامله

محصول می‌تواند قیمت دستی (`manual`) یا فرمولی (`derived`) داشته باشد. اتصال خودکار هوم‌گلد برای محصول دارای روش قیمت‌گذاری `manual` قابل فعال‌سازی است. «دستی» در تنظیم محصول و «خودکار» در اتصال هوم‌گلد دو تنظیم با مسئولیت متفاوت‌اند.

### محاسبهٔ معامله

1. مشتری نوع خرید یا فروش و مقدار یا مبلغ را وارد می‌کند.
2. فرانت از `trade/preview` نتیجهٔ قطعی سرور را می‌گیرد.
3. قیمت، مقدار و مبلغ نهایی به مشتری نمایش داده می‌شود.
4. ثبت درخواست با شناسهٔ قیمت مورد انتظار و شناسهٔ یکتای عملیات انجام می‌شود.
5. در صورت تغییر قیمت، تأیید مجدد با پیش‌نمایش تازه لازم است.

برای هر نقش، تعدیل ثابت خرید و فروش می‌تواند جداگانه اعمال شود. در قیمت دستی، اختلاف فروش از قیمت پایه کسر می‌شود؛ در اتصال هوم‌گلد، قیمت فروش از دادهٔ همان اتصال گرفته می‌شود.

| محصول تعدادی | مقدار باید عدد صحیح مثبت باشد |
| گرم یا مثقال | مقدار با حداکثر ۶ رقم اعشار |

این قواعد به شناسهٔ محصول وابسته‌اند. حذف تقسیم قیمت از فرم هوم‌گلد، تبدیل داخلی مبلغ محصول ۳ را حذف نمی‌کند. تغییر قیمت خودکار محصول ۳، حرکت پله‌ای محصول ۱ را اجرا نمی‌کند؛ تغییر دستی محصول ۳ نیز قیمت محصول ۱ با اتصال خودکار را بازنویسی نمی‌کند.

### وضعیت درخواست

```text
pending → approved → completed
        → rejected
        → cancelled
```

مشتری فقط درخواست در انتظار متعلق به خودش را می‌تواند لغو کند. مدیر درخواست را تأیید، رد یا تکمیل می‌کند. تغییر وضعیت نامعتبر با پاسخ ۴۰۹ رد می‌شود. مشخصات قیمت و محاسبهٔ زمان ثبت در درخواست حفظ می‌شود.

## ۸. کاربران، نقش‌ها و محدودیت خرید

ثبت‌نام عمومی کاربر مشتری ایجاد می‌کند. دسترسی به عملیات مدیریت، از نقش و وضعیت واقعی کاربر در بک‌اند بررسی می‌شود. غیرفعال بودن کاربر مانع استفاده از مسیرهای محافظت‌شده می‌شود.

در نقش‌ها، دسترسی به محصول و امکان خرید تنظیم می‌شود. مشاهدهٔ قیمت و مجوز معامله بر اساس دسترسی نقش کنترل می‌شوند و صرف مشاهدهٔ صفحه به‌معنای اجازهٔ ثبت درخواست نیست.

### حد خرید مقداری

در نسخهٔ فعلی، حد خرید مشتری با دو گروه **گرم** و **تعداد** مدیریت می‌شود. ورودی خالی به‌معنای نامحدود بودن آن گروه است. خریدهای در انتظار، تأییدشده و تکمیل‌شده در مصرف حد خرید لحاظ می‌شوند؛ درخواست ردشده یا لغوشده از مصرف خارج می‌شود.

برای محاسبهٔ سقف گرمی، مقدار مثقال با ضریب ۴٫۶۰۸۳ به گرم تبدیل می‌شود. سفارش فروش، خرید جدید محسوب نمی‌شود. کنترل محدودیت در سرور انجام می‌شود و صرف تغییر مقدار در مرورگر آن را دور نمی‌زند.

کد و فیلدهای قدیمی سقف مبلغی نیز در پروژه وجود دارند؛ راهنمای بهره‌برداری نسخهٔ فعلی بر تنظیم حد خرید گرمی و تعدادی است. ساختار دیتابیس را با مایگریشن‌های موجود به‌روز کنید.

## ۹. پیامک، ثبت‌نام و بازیابی رمز

سرویس پیامک از کاوه‌نگار استفاده می‌کند. برای پیامک تأیید، یک الگوی تأییدشده شامل `%token` ایجاد کنید و نام همان الگو را در محیط قرار دهید.

```dotenv
KAVENEGAR_API_KEY=your-api-key
KAVENEGAR_OTP_TEMPLATE=your-approved-template
KAVENEGAR_OTP_TTL=300
KAVENEGAR_OTP_RESEND_AFTER=90
KAVENEGAR_OTP_MAX_ATTEMPTS=5
```

| عملیات | مسیر زیر `/api/v1/auth` |
| --- | --- |
| ثبت‌نام اولیه | `POST register` |
| تأیید ثبت‌نام | `POST register/verify` |
| ارسال دوبارهٔ کد ثبت‌نام | `POST register/resend` |
| ورود | `POST login` |
| شروع بازیابی رمز | `POST forgot-password` |
| ارسال دوبارهٔ کد بازیابی | `POST forgot-password/resend` |
| تعیین رمز جدید | `POST reset-password` |
| اطلاعات کاربر فعلی | `GET me` |

کد تأیید شش‌رقمی به‌صورت پیش‌فرض پنج دقیقه معتبر است، ارسال مجدد پس از ۹۰ ثانیه ممکن می‌شود و تعداد تلاش ناموفق محدود است. تغییر رمز در فرایند بازیابی، نشست‌های قبلی را باطل می‌کند. کلید پیامک و کلید هوم‌گلد فقط در تنظیمات بک‌اند قرار می‌گیرند.

## ۱۰. قرارداد API و نمونه‌ها

پایهٔ مسیرها `/api/v1` است. درخواست‌های JSON از `Accept: application/json` و `Content-Type: application/json` استفاده می‌کنند. برای مسیر محافظت‌شده، `Authorization: Bearer <access_token>` ارسال می‌شود.

### قالب پاسخ

```json
{"success": true, "message": "OK", "data": {}, "meta": {}}
```

مبالغ ریالی API معمولاً رشته و با نام دارای `_rial` هستند. زمان‌ها UTC و ISO 8601 هستند و در رابط به تاریخ محلی تبدیل می‌شوند. محاسبات پولی را با عدد اعشاری شناور در مرورگر جایگزین نکنید.

### ثبت تنظیم سادهٔ هوم‌گلد

`PUT /api/v1/admin/homegold/products/{product_id}`

```json
{
  "commodity_id": "coin-1",
  "mode": "auto",
  "currency_multiplier": 10
}
```

مقدار API برای حالت دستی `disabled` است. مقادیر مجاز روش استفاده فقط `auto` و `disabled` هستند. فیلدهای حذف‌شده، در سرور با مقادیر ثابت جایگزین می‌شوند.

### مسیرهای مدیریت هوم‌گلد

| متد و مسیر | کاربرد |
| --- | --- |
| `GET admin/homegold` | تنظیمات، آخرین فهرست دریافتی و محصولات |
| `POST admin/homegold/refresh` | دریافت تازه و بررسی اتصال‌های خودکار |
| `POST admin/homegold/products/{id}/preview` | محاسبه بدون ثبت قیمت |
| `PUT admin/homegold/products/{id}` | ذخیرهٔ تنظیمات |
| `POST admin/homegold/products/{id}/apply` | دریافت و اعمال فوری اتصال خودکار ذخیره‌شده |

مسیرهای دریافت و اعمال فوری محدودیت ۱۰ درخواست در دقیقه دارند. تمام مسیرهای این جدول به مدیر فعال نیاز دارند.

### پیش‌نمایش و ثبت سفارش

```json
{
  "product_id": 10,
  "trade_type": "customer_buy",
  "entry_mode": "quantity",
  "quantity": "1.250000"
}
```

این ورودی به `POST trade/preview` ارسال می‌شود. برای ثبت در `POST purchase-requests`، شناسهٔ قیمت دریافتی را به همراه شناسهٔ عملیات اضافه کنید:

```json
{
  "product_id": 10,
  "trade_type": "customer_buy",
  "entry_mode": "quantity",
  "quantity": "1.250000",
  "expected_product_price_id": 25,
  "client_reference": "50e75b94-58e3-4f44-8961-4e9f7e54f189"
}
```

برای تلاش دوبارهٔ همان عملیات، همان `client_reference` حفظ می‌شود. برای عملیات جدید UUID تازه بسازید. شناسه‌ها در این مثال فرضی‌اند.

| کد HTTP | برخورد معمول رابط |
| --- | --- |
| ۴۰۱ | ورود دوباره |
| ۴۰۳ | نمایش نداشتن مجوز |
| ۴۰۴ | نمایش نبودن رکورد |
| ۴۰۹ | تعارض؛ برای `PRICE_CHANGED` نمایش پیش‌نمایش تازه |
| ۴۲۲ | نمایش خطاهای اعتبارسنجی |
| ۴۲۹ | صبر و تلاش مجدد پس از محدودیت درخواست |

برای فهرست کامل مسیرها، `php artisan route:list --path=api` را اجرا کنید؛ این دستور مرجع دقیق نسخهٔ نصب‌شده است.

## ۱۱. انتشار قیمت و حضور کاربران

در محیط دارای Reverb، تغییر قیمت پس از ثبت موفق در دیتابیس از مسیر Broadcasting به کانال خصوصی نقش منتشر می‌شود. مرورگر با Laravel Echo/Pusher به کانال مجاز خود متصل می‌شود. نسخهٔ قیمت مانع جایگزینی دادهٔ تازه با پاسخ قدیمی می‌شود.

برای Reverb، شناسهٔ عمومی برنامه در زمان build فرانت لازم است. راز اتصال فقط در بک‌اند می‌ماند. وب‌سرور باید WebSocket را به سرویس داخلی هدایت کند و Reverb به‌عنوان فرایند پایدار اجرا شود.

در حالت بدون `VITE_REVERB_APP_KEY`، مسیر فرانت برای تازه‌سازی قیمت و اطلاعیه از polling استفاده می‌کند؛ بستهٔ cPanel با همین حالت ساخته می‌شود. بنابراین دریافت قیمت از هوم‌گلد، ثبت آن در سرور و رساندن قیمت به مرورگر سه مرحلهٔ جداگانه‌اند.

برای مشاهدهٔ آنلاین بودن کاربران، heartbeat هر ۳۰ ثانیه ارسال می‌شود و مدت حضور پیش‌فرض حدود ۹۰ ثانیه است. آنلاین بودن کاربر با وضعیت «مدیر آنلاین» که ثبت معامله را کنترل می‌کند، مفهوم متفاوتی دارد.

## ۱۲. استقرار روی cPanel و Docker

### انتخاب محیط

| مورد | Docker یا سرور اختصاصی | cPanel اشتراکی |
| --- | --- | --- |
| دیتابیس نمونه | PostgreSQL | MySQL |
| کش و نشست | Redis | فایل |
| صف | Worker مستقل | اجرای هم‌زمان (`sync`) |
| نمایش قیمت | Reverb با زیرساخت لازم | polling بدون کلید Reverb |
| دریافت هوم‌گلد | Scheduler مستقل | Cron دائمی |

### ساخت بسته

```bash
./scripts/build-cpanel-package.sh
```

خروجی `dist/shahrazgold-cpanel.zip` دو پوشه دارد:

```text
/home/ACCOUNT/shahrazgold-app   کد خصوصی و تنظیمات
/home/ACCOUNT/public_html      فرانت و ورودی وب لاراول
```

برای آپدیت نصب موجود، اسکریپت `scripts/build-cpanel-update-package.sh` بستهٔ `dist/shahrazgold-cpanel-update.zip` را می‌سازد. این بسته برای حفظ `.env`، فایل‌های زمان اجرا و تنظیمات وب موجود طراحی شده است. پس از آپدیت، تمام مایگریشن‌های اجرا‌نشده، از جمله جدول اتصال هوم‌گلد، باید اجرا شوند.

### تنظیم محیط واقعی

```dotenv
APP_ENV=production
APP_DEBUG=false
APP_URL=https://example.com
DB_CONNECTION=mysql
DB_HOST=localhost
DB_DATABASE=ACCOUNT_shahrazgold
DB_USERNAME=ACCOUNT_shahrazgold
DB_PASSWORD=your-database-password
CACHE_STORE=file

BROADCAST_CONNECTION=log
SHAHRAZGOLD_PRESENCE_DRIVER=cache

```

SSL دامنه را فعال کنید و اطلاعات واقعی دیتابیس و سرویس‌های خارجی را جایگزین نمونه‌ها کنید. فایل `.env` در مسیر خصوصی برنامه نگه‌داری می‌شود.

### ساخت مدیر و نصب

فایل نمونهٔ `storage/app/deployment-admin.json.example` را به `deployment-admin.json` کپی و اطلاعات مدیر واقعی را وارد کنید. فرایند نصب، فایل دارای رمز خام را پس از موفقیت حذف می‌کند.

برای نصب یک‌باره، Cron موقت اجرای `deploy-cpanel.php` را بسازید و لاگ `storage/logs/cpanel-deploy.log` را بررسی کنید. پس از مشاهدهٔ `exit=0`، Cron نصب را حذف کنید. **Cron دائمی Scheduler هوم‌گلد مستقل است و باید باقی بماند.**

در محیط دارای Terminal:

```bash
php artisan migrate --force
php artisan config:clear
```

### آزمایش بعد از انتشار

1. صفحهٔ اصلی، `/admin-login` و `/up` باز شوند.
2. API دسته‌ها و محصولات پاسخ دهد.
3. ورود مدیر و دسترسی نقش مشتری بررسی شود.
4. دریافت هوم‌گلد موفق و یک اتصال آزمایشی درست تنظیم شود.
5. با بستن پنل، Scheduler همچنان قیمت محصول خودکار را دریافت کند.
6. پیش‌نمایش خرید و فروش و ثبت درخواست در شرایط کنترل‌شده بررسی شود.

## ۱۳. تست و گزارش کنترل کیفیت

### دستورهای بررسی

```bash

docker compose exec -T app php artisan test
npm --prefix frontend run build:htdocs

### وضعیت بررسی این تحویل

| بررسی | نتیجه |
| --- | --- |
| تست اختصاصی هوم‌گلد | ۳۱ تست موفق؛ دریافت زمان‌بندی‌شده، قیمت مستقیم، اعتبار، خطا و دسترسی |
| build فرانت | موفق |
| ESLint فایل پنل هوم‌گلد | موفق |
| مجموعهٔ عمومی بک‌اند | ۸۷ موفق و ۱۰ ناموفق |
| بررسی نسخهٔ پایهٔ قبلی گیت | ۵۶ موفق و همان ۱۰ تست عمومی ناموفق |

خطاهای عمومی در مجموعهٔ `TradeAndPurchaseRequestTest` مشاهده شدند. نسخهٔ پایهٔ `31c25fc` نیز جداگانه با همان محیط بررسی شد و همان ۱۰ خطا را داشت؛ بخشی از آن‌ها با نبود دسترسی محصول در دادهٔ تست مرتبط‌اند. بنابراین این تحویل به‌معنای سبز بودن کل مجموعهٔ تست پروژه نیست و این موارد نیازمند اصلاح جداگانه‌اند.

در مرور قبل از پوش، یک ارجاع نامعتبر به متغیر در مسیر تغییر گام قیمت اتصال خودکار اصلاح شد و برای ممنوعیت این تغییر در حالت خودکار و امکان آن در حالت دستی، تست اضافه شد.

### آزمون کاربردی پیشنهادی

1. یک محصول آزمایشی را در حالت خودکار ذخیره کنید.
2. زمان دریافت موفق و قیمت ثبت‌شده را بررسی کنید.
3. صفحه را ببندید و پس از چند نوبت دوباره باز کنید؛ زمان دریافت باید تازه شده باشد.
4. با منبع دارای تغییر قیمت، قیمت خرید و فروش سایت را با تبدیل پول انتخابی مقایسه کنید.
5. به حالت دستی برگردید؛ دریافت فهرست هوم‌گلد نباید قیمت دستی سایت را عوض کند.
6. قطع سرویس و انقضای قیمت را فقط روی محیط آزمایشی شبیه‌سازی کنید.

python3 scripts/build-project-guide.py
```

فایل `docs/PROJECT_GUIDE.fa.html` را در Chrome باز و از Print با اندازهٔ A4 و فعال بودن چاپ پس‌زمینه‌ها، PDF تهیه کنید. نسخهٔ PDF این تحویل با فونت وزیر داخلی و شمارهٔ صفحه ساخته شده است.
